# AI Mode

Замкнутый цикл поверх выбранного режима G-Helper. Раз в 1 с (в горячих зонах раз в 0,5 с) он читает сенсоры и двигает потолок частоты и EPP в активной схеме питания Windows, чтобы держать температуру CPU у цели. PL1/PL2, вентиляторы и сам режим остаются за G-Helper. На AMD функция скрыта.

Сейчас реализованы этапы 1–3: запись в план питания, телеметрия с логом и ПИ-регулятор с UI. Модели (этапы 5–6) пока нет, источник решений всегда «Регулятор».

## Как испытывать

1. «Вентиляторы + Мощность» → вкладка CPU → секция **AI Mode** внизу, под «Применить лимиты мощности».
2. Включить галку **AI Mode**. Она хранится отдельно для каждого режима (Silent / Balanced / Turbo).
3. **Целевая температура** (70–95 °C, по умолчанию 87) и **Офсет** (2–10 °C, по умолчанию 5). Рядом с офсетом показывается итоговый порог: «агрессивно выше 92 °C». Сумма цели и офсета не превышает 100 °C: если превышает, офсет уменьшается сам.
4. **Целевая частота** (3000–5400 МГц, по умолчанию 4400) — потолок под тяжёлой нагрузкой. **Минимальная частота** (1800–4400 МГц, по умолчанию 3000) — ниже неё регулятор не опускает частоту. Минимальная не может быть выше целевой: если сдвинуть один слайдер за другой, второй подвинется сам.
5. Строка статуса обновляется раз в секунду: источник решений, зона, температура, загрузка CPU, текущий потолок, EPP и лимит по нагрузке.
6. После смены режима регулятор стартует через 5 с: в это время G-Helper и прошивка применяют режим. В статусе в это время «Пауза: запуск…».
7. **Запись лога телеметрии** пишет CSV в `%AppData%\GHelper\ai_logs\`, кнопка «Логи» открывает эту папку. Лог пишется и при выключенном AI Mode — так снимается базовая линия для сравнения со стоковым режимом.
8. На главном окне к названию режима добавляется « · AI», когда AI Mode включён для текущего режима.

Что смотреть при тесте:
- В HWiNFO: частота ядер, температура CPU, флаги троттлинга (Thermal Throttling, PROCHOT).
- Под постоянной нагрузкой (Cinebench 10 мин): температура должна держаться в пределах T ± 2 °C, потолок частоты не должен колебаться больше чем на 400 МГц.
- При старте тяжёлой нагрузки на GPU (PIE в UE5, игра) потолок CPU снижается заранее, по росту мощности GPU, а при перегреве срабатывает агрессивная зона.
- В CSV-логе колонки `zone`, `cap_mhz`, `epp` и `cpu_temp`.

## Зоны

| Зона | Условие | Такт | Потолок частоты | EPP |
| --- | --- | --- | --- | --- |
| Холодная | t < T − 3 | 1 с | +200 МГц за такт до «без лимита» | −5 за такт до значения режима |
| Рабочая | T − 3 ≤ t ≤ T + Δ | 1 с | ПИ по ошибке (T − t), шаг не больше ±200 МГц | без изменений |
| Агрессивная | t > T + Δ, выход при t < T + Δ − 2 | 0,5 с | −500 МГц за такт | +10 за такт, не выше 80 |
| Аварийная | t ≥ 98 или рост > 3 °C/с в агрессивной зоне, выход при t < T | 0,5 с | сразу не выше 2400 МГц | 80 |

- Перед сравнением с порогами температура сглаживается EMA (α = 0,5). Аварийный порог 98 °C сравнивается с сырым значением.
- ПИ реализован в скоростной форме: интегратором служит сам потолок. Поэтому он заморожен вне рабочей зоны и не может накопиться за пределы диапазона потолка (anti-windup).
- Упреждение по GPU: если мощность GPU выросла за 5 с больше чем на 15 Вт, потолок снижается на 20 МГц за каждый ватт прироста. Снижение делается один раз на каждый скачок.
- При загрузке CPU ниже 10 % потолок не трогается, в статусе «простой». Аварийная зона работает и в простое.
- **Учёт нагрузки.** Верхняя граница потолка зависит от сглаженной загрузки CPU. При загрузке до 30 % потолок не ограничен, так что одно-двухпоточные всплески бустятся до максимума. От 70 % потолок равен целевой частоте (4400 МГц). Между 30 и 70 % граница меняется линейно. Если загрузка неизвестна, она считается тяжёлой. Когда начинается тяжёлая нагрузка, потолок сразу опускается до этой границы, не дожидаясь нагрева.
- **Минимальная частота** — нижняя граница для холодной, рабочей и агрессивной зон. Ниже неё уходит только аварийная зона (2400 МГц при 98 °C).
- Если граница выше `ai_max_mhz` (5400), регулятор пишет 0, то есть без лимита.

## Безопасность

| Ситуация | Что происходит |
| --- | --- |
| Выход, выключение галки, смена режима | исходные значения восстанавливаются |
| Падение или убийство процесса | при следующем старте значения восстанавливаются из `ai_restore.json` |
| Необработанное исключение, завершение сеанса Windows | исходные значения восстанавливаются |
| Сон | перед сном значения восстанавливаются; после пробуждения старт через 5 с с обнулённым состоянием |
| Батарея | пауза с восстановлением значений; при подключении к сети работа продолжается |
| Нет температуры CPU 3 такта подряд или значение вне 0–110 °C | пауза с восстановлением до появления сенсора |
| Кто-то другой изменил наши значения или сменил схему питания | разовое изменение принимается: при смене схемы старой схеме возвращаются исходные значения и снимается новая схема; изменённые значения становятся новыми исходными. В `log.txt` пишется строка `AI: external change` — что именно и на что изменилось |
| Значения меняют 3 раза за минуту | остановка, восстановление и уведомление «план постоянно меняет другая программа» |
| Ошибка записи в план 5 раз подряд | остановка и уведомление |
| Запущен Armoury Crate | регулятор не стартует, в статусе «Пауза: Armoury Crate» |

При включении галки показывается предупреждение, если запущен Armoury Crate, если режим переключает режим питания Windows на что-то кроме «Сбалансированного» (оверлей может перекрывать EPP, потолок частоты при этом работает) или если ноутбук на батарее.

## Настройки только через config.json

Файл `%AppData%\GHelper\config.json`. Значения целые; где нужна дробь, она задаётся в процентах.

| Ключ | По умолчанию | Что делает |
| --- | --- | --- |
| `ai_mode_<N>`, `ai_target_<N>`, `ai_offset_<N>` | 0 / 87 / 5 | то же, что галка и слайдеры температуры (N — номер режима) |
| `ai_min_mhz_<N>`, `ai_target_mhz_<N>` | 3000 / 4400 | слайдеры минимальной и целевой частоты |
| `ai_light_util`, `ai_heavy_util` | 30, 70 | загрузка CPU (%), до которой потолок не ограничен и от которой он равен целевой частоте |
| `ai_mode_delay` | 5000 | задержка старта после смены режима, мс |
| `ai_log` | 0 | запись CSV |
| `ai_explore` | 0 | «исследование»: в холодной и рабочей зонах случайный потолок на 20–40 с, для сбора обучающих данных; агрессивная и аварийная зоны работают как обычно |
| `ai_kp`, `ai_ki` | 150, 20 | коэффициенты ПИ: МГц/°C и МГц/(°C·с) |
| `ai_pi_step` | 200 | максимальный шаг ПИ за такт, МГц |
| `ai_cold_step` | 200 | рост потолка в холодной зоне, МГц за такт |
| `ai_aggressive_step` | 500 | снижение потолка в агрессивной зоне, МГц за такт |
| `ai_emergency_cap`, `ai_emergency_temp`, `ai_emergency_rise` | 2400, 98, 3 | аварийная зона: потолок МГц, порог °C, скорость роста °C/с |
| `ai_ema` | 50 | α сглаживания, в процентах |
| `ai_max_mhz` | 5400 | потолок, выше которого пишется «без лимита» |
| `ai_gpu_rise`, `ai_gpu_mhz_per_w` | 15, 20 | упреждение по GPU: порог прироста в Вт и МГц на каждый Вт |
| `ai_idle_util` | 10 | ниже этой загрузки CPU (%) потолок не трогается |
| `ai_tick`, `ai_fast_tick` | 1000, 500 | длительность такта, мс |
| `ai_debug_cap`, `ai_debug_epp` | — | фиксированные значения при выключенном AI Mode (отладка этапа 1) |

Изменения в config.json применяются при следующей смене режима или переключении галки.

## Лог

`%AppData%\GHelper\ai_logs\YYYY-MM-DD_HHMMSS.csv`: новый файл на каждый запуск, ротация по 50 МБ, хранятся последние 20 файлов. Колонки:

```
ts,cpu_temp,gpu_temp,gpu_power,gpu_util,cpu_fan,gpu_fan,cpu_util,cpu_freq_eff,cpu_power,mode,on_ac,cap_mhz,epp,zone,policy,pred_temp,read_ms,ceiling_mhz
```

Если сенсор не ответил, поле пустое. `read_ms` — время чтения всех сенсоров за такт, должно быть меньше 50 мс. `ceiling_mhz` — лимит по нагрузке на этом такте. `zone` принимает значения cold / working / aggressive / emergency / idle, `policy` — pi / explore / paused / off.

Ход регулятора и паузы пишутся также в `%AppData%\GHelper\log.txt` (строки с префиксом `AI`).

## Сверка с репозиторием (этап 1)

| В плане | В репозитории |
| --- | --- |
| `PowerNative` | `app/Mode/PowerNative.cs`. Его P/Invoke приватные, поэтому AI Mode объявляет свои в `PowrProfSettings.cs` |

| `ModeControl` | `SetPerformanceMode` → `AiModeHooks.OnModeChanged()` |

| Armoury Crate | `AsusService.IsArmouryRunning()` |

## Открытый вопрос: перекрывает ли оверлей EPP

Проверяется на ноутбуке. Поставить `ai_debug_epp: 60` и выключить AI Mode. По очереди включить режимы с режимом питания Windows Best Power Efficiency, Balanced и Best Performance и сравнить фактический EPP в HWiNFO или ThrottleStop с 60. Строка `AI Overlay` в `log.txt` показывает, какой оверлей эффективен. Если EPP перекрывается, при включённом AI Mode нужно ставить оверлей Balanced.
